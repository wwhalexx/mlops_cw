# Dataset card

## Происхождение

Russian Language Toxic Comments: комментарии с Pikabu и 2ch.
Источник: https://www.kaggle.com/datasets/blackmoon/russian-language-toxic-comments,
версия **1**. Kaggle API метаданных указывает **GPL 2** (проверено 14.11.2026).
Это указание издателя набора; оно не подтверждает согласие каждого автора комментария.
Проект получает CSV непосредственно из источника и не включает его в историю Git.
Проверить метаданные можно запросом:
https://www.kaggle.com/api/v1/datasets/list?search=russian-language-toxic-comments

Сырой `labeled.csv`: SHA-256
`25e75c5b98b82bff4c4f987f452c7eea9735b83744b43bbd31187c3fc792e18b`.
Команда `toxic-mlops download` скачивает ZIP версии 1 и проверяет содержимое.
Если источник недоступен, допустимо вручную положить исходный файл по настроенному
пути: SHA-256 должен совпадать; автоматически принимать другую версию запрещено.

## Поля и область применения

- `comment`: текст, единственный источник признаков.
- `toxic`: бинарная разметка, 0 — нетоксичный, 1 — токсичный.
- 14 412 исходных строк; 9 586 класса 0, 4 826 класса 1.
- `row_id`, `group`, `split`: технические идентификаторы, не признаки модели.
- Нет автора, времени, идентификатора треда и контекста. Возможны неоднозначные
  и ошибочные метки, тематические и социальные смещения, ненормативная лексика.

## Подготовка и версии

Оба варианта используют одинаковый очищенный состав строк: HTML entities и теги,
Unicode NFC и пробелы; минимум 15 символов. По ключу NFKC/lower/ё→е целиком
исключаются группы с разными метками, непротиворечивые дубли сокращаются до одного.
Для corpus v1 ожидается 14 112 строк, 4 700 положительных; фактические результаты
публикуются в `reports/experiments.json`.

- **v1**: минимальная очистка; сохраняются регистр, пунктуация и лексика.
- **v2**: v1 + lower/ё→е + замена URL и упоминаний на `url` и `user`.

Подготовленные CSV имеют SHA-256 в `data.versions` отчёта. Идентификатор версии
полон только вместе с raw SHA, commit/source SHA и параметрами подготовки.
Различия правил очистки относительно прежнего учебного notebook документированы:
HTML entities декодируются итеративно для вложенных entities.

## Разбиение и защита от утечки

Почти дубли объединяются в компоненты связности: cosine ≥0.95 по hashed символьным
5-граммам, минимум 40 символов, 2^18 признаков. Коллизии и невыявленные перефразы
возможны. Группы строятся без меток; конфликтующие точные ключи проверяются отдельно.
StratifiedGroupKFold: 20 folds, shuffle, seed 42; folds 0–2 — test, 3–5 — validation,
6–19 — train. Разбиение не меняется между версиями preprocessing и экспериментами.
Split CSV имеет отдельный SHA-256. Все TF-IDF fit выполняются только на train.
Validation выбирает конфигурацию; test оценивает только победителя.

Дедупликация использует весь корпус как техническую подготовку оценки; это не
означает, что test полностью неизвестен на уровне метаданных. Test не используется
для обучения словаря, IDF, классификатора или настройки гиперпараметров.
